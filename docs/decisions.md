| D-22 | 2026-11-02 | Music, step 1 (owner request): `music.control` and `music.now_playing` use the operating system's media session, not any one app and not the network (Windows: the system media session for pause, play, next, previous and now playing; the system volume keys for volume and mute, about 10% per command). Both are Low risk. Exact whole-sentence phrases ("pause", "next song", "volume up", "what's playing") run locally through the gateway whether or not you are online, with no model round trip, so they cost nothing; any other sentence still goes to the model, which also has the tools. Plain "mute" stays the microphone; "mute the music" or "mute the sound" is the system mute (a toggle). "What's playing" returns names from another app, so it counts as outside content (taint). **macOS (added 2026-11-02): the Spotify and Music apps through fixed AppleScripts run by `/usr/bin/osascript` (no text from the model, a title or the user is ever put in a script; a player that is not already running is never launched, checked with `pgrep -x`; the one running and playing is used, Spotify first on a tie; volume and mute use the system volume setting and need no permission). The first use needs the person's Automation permission, and without it the tool says where to switch it on.** The Linux adapter is not written yet and says so. Step 2: "play X" is built (issue #68, contract #75): the official Spotify Web API with Authorization Code + PKCE (no client secret), the sign-in in the system browser from Rust on the loopback address `http://127.0.0.1:43597/callback` (a fixed port, because Spotify's dashboard rejects a redirect address without one) with a random `state`, the refresh token in the OS keychain under its own account, scopes `user-modify-playback-state` and `user-read-playback-state` only. One tool, `music.play` (Low risk, 30 s timeout (the client gives up after 20 s with a trace), result counts as outside text), searches and plays the top match; "play <words>" (up to 8 words) is answered locally with no model call. Likes and playlists are not built. **Windows finding (2026-11-03, owner's laptop):** asking Spotify to play a track alone (`uris`) is accepted (204) but the desktop app clears its player; asking for the track inside its album (`context_uri` with the track as `offset`) works. So the cloud route asks the album way first and the track alone as the fallback, and starts the installed Spotify app (the fixed `spotify:` address) when no device is listed. | proposed |
